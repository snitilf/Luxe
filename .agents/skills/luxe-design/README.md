# The Luxe design system

Luxe is a local editor for agent-generated HTML artifacts.
An agent writes a page, Luxe opens it in a browser, a human points at elements or selects text and annotates them, and that feedback goes back to the agent.

The system this skill describes is warm, light and neutral-first.
The page being reviewed is the only thing on screen that should be interesting.
Everything the tool itself draws is paper, ink, hairlines and one accent.

## The three decisions everything follows from

**Light only.**
One theme.
No dark palette, no `prefers-color-scheme` branch, no toggle, in the chrome or in anything an artifact is told to generate.
This is a decision rather than an omission, so do not add a dark variant "for completeness".

**Colour is information.**
Charts get colour because colour is the encoding.
Status gets colour because a state has to be distinguishable at a glance.
The annotation stroke gets colour because a neutral outline is invisible against a hairline border, and annotation is the single most important interaction in the product.
Nothing else gets colour.

**The type system ships with the app.**
Both families are bundled and served locally, not fetched from a font CDN.
The tool has to work offline, and a published artifact may sit behind a policy that blocks external hosts.

## Type

Two families: a sans for everything an interface says, and a mono for anything the reader is meant to read literally.
There is no serif and there is no third family.
The sans carries slightly negative tracking; the mono carries none, because negative tracking fights a monospace face's own metrics.

Four sizes: heading, body, control, label.
Nothing between them, nothing above the heading.
Two weights: regular and medium.
No bold and no light, so emphasis is weight 500 or a size that is already in the scale.

Uppercase belongs to micro-labels alone and takes the positive tracking token, because uppercase closes up.
Headings and body are never uppercase.

See `preview/type-families.html` and `preview/type-scale.html`.

## Geometry

Five radii, each with one job: nav, inner, card, bubble and pill.
Nest inward, never outward.
The bubble radius is the card radius with the speaker-side bottom corner tightened, which is what points a chat bubble at its author without a tail.

Icons are inline stroke SVG on a 24 viewBox at two sizes, nav and card, always `currentColor`, round caps and joins.
No icon font, no sprite sheet, no CDN, no emoji.
Never fill an icon sitting beside control-size text.

Hierarchy comes from three surface planes plus hairlines.
Resting surfaces carry no shadow.
Exactly one shadow token exists and it belongs to the modal, which genuinely floats above a scrim.

See `preview/geometry-radii.html`, `preview/geometry-elevation.html` and `preview/brand-iconography.html`.

## Surfaces and ink

Three planes: the canvas holds the page and the artifact, the middle plane holds the toolbar and raised panels, the top plane holds cards, inputs, modals and agent bubbles.
Two rules: the hairline for ordinary borders, dividers and chart gridlines, and the emphasis rule for table header rules and control borders.

Three inks.
The first carries body, headings and values.
The second carries labels, metadata and axis text.
The third is decoration only: it sits below the 4.5:1 text floor, so it may tint a divider, a disabled label, a tick mark or a placeholder, and it must never carry a value, a caption or anything a reader needs.
Reaching for the third ink on real text means the answer was the second ink.

The cocoa fill is a separate value from the body ink, deliberately.
Type and filled surfaces are different jobs, and collapsing them is what makes a primary button read as near-black.
The cocoa fill carries the primary button, the user chat bubble, the annotate toggle track when on, and tooltip backgrounds, always paired with its own text token.

See `preview/colors-surfaces.html`, `preview/colors-ink.html` and `preview/colors-dark-fill.html`.

## The one accent

The gold is the element annotation outline and the selected-text wash.
That is the entire list.
It is not the focus ring, not a chart colour, not a shape colour in a diagram, not a link colour and not a button.

The focus ring is the info slate.
Upstream used one ring for both annotation and focus on the argument that both mean "attention is here".
This system splits them, because a durable mark the user made and will send to an agent is a different event from transient keyboard position.

See `preview/colors-accent.html` and `preview/states-annotation.html`.

## Status

Four roles: success, warning, error and info.
Each is a triple of a foreground, a tint and a border, and each is used as a set.
Status always ships with an icon and a text label, never colour alone.

Error shares a colour family with the warm chart slots.
The separation is carried by the lightness register, the tinted container and the icon-plus-label rule, plus one rule about charts: a series that itself means good or bad wears status tokens rather than a categorical slot.

See `preview/colors-status.html`.

## Charts

Eight categorical slots in a fixed order.
The order is the colour-blind safety mechanism, not decoration, so assign from slot one upward and never cycle or reshuffle.
Adjacent pairs separate cleanly, so lines, stacked bars and grouped bars may use all eight.
All-pairs separation holds for four, so scatter, bubble, choropleth and small multiples cap at four series.

Three slots sit below 3:1 against the canvas.
That makes one rule load-bearing: **every chart carries direct labels, printed values, or a table view beside it**.
A legend alone is not sufficient, and this has to be a default inside the chart component rather than something left to whoever authors a page.

Marks are token-specified: stroke width, end-dot size, the canvas-coloured ring around end dots, the gap between stacked segments.
Gridlines are hairlines, axis text is the second ink at label size.

Two ramps exist for magnitude: a sequential blue family, monotonic in lightness so it survives greyscale, and a diverging ramp whose midpoint is the system's warm neutral so that "no change" reads as paper.
Ramps encode magnitude and slots encode identity.
Never mix them in one chart, and never build a ramp by tinting a categorical slot.

See `preview/charts-palette.html` and `preview/charts-ramps.html`.

## Code and diff

Code sits on its own plane with a hairline border, set in the mono at label size.
The syntax theme is bespoke rather than borrowed, and every syntax ink is a dark, so all of them survive on both diff tints.
Punctuation is the one decoration-grade ink in the set.
The added and removed rows each have a background tint and a gutter colour; the hunk-header tint is applied by the surrounding component, because a theme file has no key for it.

See `preview/code-and-diff.html`.

## Diagrams

Diagrams are authored in Mermaid, not built from divs and flexbox.
Mermaid handles node placement and edge routing, converts to editable scenes inside the editor, and is themed through a single `themeVariables` block so every diagram inherits the system automatically.
A bare theme name is not enough: Mermaid's own defaults ship fills and borders that look like a foreign object dropped into the page.

The block itself lives in `src/mermaid-theme.js` and is printed, ready to paste, by `npx -y editeur-luxe design`.
Import it or paste it; do not retype it.
The annotation gold is reserved and is never used as a shape colour.

The one form Mermaid cannot express is a node graph where each node carries an icon well, a title, a subtitle and connection ports.
That specific form is positioned HTML over an SVG edge layer.
Flows, architecture, state and sequence diagrams are Mermaid, and a diagram that does not need per-node cards is not an exception.

## Chrome components

The editor chrome is the reference implementation of everything above.
The component contract, in token terms:

| Component | Specification |
| --- | --- |
| Toolbar | Middle plane, hairline underneath, the wordmark alone at the brand size in Newsreader medium and the cocoa. No file name: the path lives in the overflow menu |
| Primary button | Cocoa fill with its paired text; hover moves to the hover fill; disabled uses the disabled fill and ink |
| Ghost button | Top plane, emphasis border, first ink |
| Annotate toggle | On: cocoa track, ivory knob. Off: the off-track token, ivory knob |
| Annotation outline | Annotate stroke width in gold, 2px offset, numbered gold badge whose number is the first ink |
| Text selection | The gold wash |
| Agent bubble | Top plane, hairline border, left aligned, bottom-left corner tightened |
| User bubble | Cocoa fill with its paired text, right aligned, bottom-right corner tightened |
| Queued pill | Dashed emphasis border on the canvas, second ink, clock glyph |
| In-flight pill | Solid hairline on the top plane, second ink |
| Composer | Top plane, nav radius, hairline border, queued pills above the input and never inside it |
| Modal | Top plane, hairline border, card radius, the one shadow, over the scrim |
| Tooltip | Cocoa fill with its paired text |
| Ended state | Toolbar chip on the hairline fill at the second ink, chrome to the ended opacity, annotation hue removed and outlines dropped to the emphasis rule |

Agent and user are told apart by surface and alignment, not by two hues.
Upstream spent one colour on the agent and another on the user; this system does not, because alignment already says it.

Destructive actions carry no colour.
Ending a session is irreversible, but it is not a status, and colour here is spent on charts, status and the annotation stroke.
A destructive action is a ghost button with a plain sentence beneath it saying what it does.

See the cards in the Components group.

## Copy

Sentence case for user-facing labels.
Lowercase for command names.
No emoji anywhere, in labels, headings, buttons or errors.
Name things precisely when they are technical and plainly when they are not.

## The adherence lint

```sh
node scripts/check-design-adherence.js                       # the skill itself
node scripts/check-design-adherence.js path/to/artifact.html  # your own output
```

It reads `adherence.json`, which is generated from the token file, so it enforces the current system rather than a list of families someone typed once.
It rejects colour literals anywhere in a file, font families outside the two bundled faces, font sizes outside the four, font weights outside the two, and radii outside the geometry scale.

The one exception is SVG artwork, which cannot read a custom property.
There a literal is allowed, but only if it is a value that exists in the token file, which is what stops the mark and the favicon drifting apart.

## Known gaps

The sequential and diverging ramps have not been exercised in a rendered heatmap or diverging chart, so check a real render before trusting their middle steps.
The mark specifications for line charts are likewise unexercised.
Every specimen so far has been viewed on macOS; bundling the type is what should make this stop mattering, but it has not been confirmed on Windows.
Line heights and spacing are not part of the specification: the two line-height tokens are the values the reference implementation renders at, and there is deliberately no spacing scale, because inventing one would be inventing system rules that nothing has validated.
