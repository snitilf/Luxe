Luxe test instrument

Kitchen sink

One page that exercises every capability Luxe has. Each section below states what it covers and exactly what to click. Nothing here is a mock: every control calls the real window.luxe SDK that Luxe injects at serve time.

Affordances Luxe adds by itself

  • Annotation mode toggles with Ctrl + i (or Cmd + i).
  • In annotation mode, clicking any element opens an annotation card for it.
  • Drag-selecting text queues a text-range annotation instead of an element one.
  • Every Mermaid diagram gets a zoom strip and an "Edit as whiteboard" button.
  • The layout audit reports clipped or overflowing regions from the chrome.
  • Scroll position is restored when the artifact reloads.

Ground rules while testing

  • Controls only queue feedback. Nothing leaves until you press Send to Agent in the Luxe chrome.
  • Selected state and queued state are shown separately under every question.
  • Re-submitting the same question replaces its unsent answer, because each one carries data-luxe-question.
  • Native controls stay clickable in annotation mode; only custom elements need data-luxe-action.

A heading that is its own annotation target

The paper canvas is the first decision the system makes and everything else is downstream of it. A warm off-white reads as a document rather than as an application window, which is the whole point: the artifact is something you review, not something you operate. Once the canvas is warm, pure white stops being the background and becomes a material, so a white card genuinely lifts off the page without needing a shadow to say so. The cocoa fill then has only one job, which is to be the single dark object on the page, and spending it anywhere else costs the page its only real emphasis. Colour is reserved for data and for status, and the eight categorical slots are ordered rather than chosen, because the order is what keeps a chart legible for a colour-blind reader. Every one of those choices is testable by looking at this page, which is why the page exists.

  • The canvas is warm, so white is a material and not a background.
  • The cocoa fill is the only dark object, so it is never decoration.
  • Headings are serif; body copy, labels and controls stay sans.
  • Colour is spent on data and status, and on nothing else.

Section 6

The cocoa panel

The one dark object on the page. Inline code, keyboard keys and marks all get contrast repairs from the Luxe baseline when they land on a dark fill, and this is where to confirm they took.

Try: read the three inline treatments below against the fill. If any of them still shows the light-surface background, the baseline did not apply. Then check that the chart sits on its own paper plate and not on the cocoa.

Contrast repairs, on the fill

Inline code such as window.luxe.queuePrompt() keeps its own plane here: the baseline swaps in a translucent light background instead of the light-surface one it would otherwise inherit.

Keyboard keys stay readable too: press Ctrl + i to toggle annotation mode, and Esc to dismiss the card. Those are bare kbd elements, which take the translucent plane above. DaisyUI's .kbd brings a light key of its own instead, so the baseline gives it the ink that belongs on that key rather than the one for the fill behind it: Ctrl + i reads here too.

A mark on the fill is highlighted like this, and the annotation gold stays reserved for annotation rather than becoming a decorative highlight.

Accordion

Why does the queue not send by itself?

Because the human decides what the agent hears. Artifact controls may queue only; transmission is confirmed from the Luxe conversation chrome.

Why one submit control per question?

A radio change is not an answer, it is a thought in progress. Queueing on every change fills the queue with drafts the reviewer never meant to send.
